# 容量範圍決策（已確認）

確認依據：訪談回覆 `Q1 是 Q2 是`、`Q3 是 Q4 是`。本決策記錄範圍與排程；最終矩陣仍待容量結果，訪談共同理解確認後才執行新方案。

CPU 盤點 [Job 49466](../43-49466/README.md) 顯示長蛋白的固定前四個候選在兩圈 halo／896 預算下均不可行；預先提出的正式前八個候選中，第八個（group 95）的最小種子 region 為 883，可放進同一預算。這是幾何盤點，尚無該 group 的模型容量證據。

維持原本 896 預算，在剩餘核准 GPU Job 中將先導候選擴展為同一固定順序的前八個；保留已送出之前四候選 Job，記為不同先導矩陣版本，不替換或刪除任何原候選。每個 Job、總 Job 數、同時使用 GPU 數與時間上限維持原核准額度。正式矩陣仍須等容量結果確認。

長蛋白兩圈 halo 在這八個候選中僅一個可行，其比較只代表該候選產生的 loss-group 集合；同一候選的三個 replica 不當成三個獨立空間候選。

剩餘三個 GPU Job 依序為短幀訓練步、250 幀 forward、250 幀訓練步。各 Job 先處理 `6sup_A` R1，再處理三個基準蛋白 R1，最後補 R2／R3。額度內未跑到的項目逐一保留；必要驗收尚未完成時，Ticket 2 不勾選。

另：896 無法容納長蛋白全部一圈種子（最大 910）。選定候選的可行容量不能聲稱正式資料集的一般 training startup 已通過；正式訓練仍保留全種子預算檢查。可行子集的近似驗證須揭露此限制。
