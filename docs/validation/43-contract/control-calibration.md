## 絕對容差（納入 250 幀後數字不變）

建議控制一致性判定：loss 絕對差不超過 `2e-6`；每個參數群的梯度差 RMS 不超過 `1e-7`，實際更新差 RMS 不超過 `2e-6`。必須同時符合有限性、相同 noise／mask hash、有效分母、t、初始權重與 optimizer 狀態；不能以跨群平均掩蓋單群失敗。

工程餘裕的選法：取兩種幀數控制合併後的最大差異的十倍，再向上取下一個 1／2／5 十進位值。loss 另使用 `10 * FP32 epsilon * max(1, 已觀察的 |reference loss|)` 作底線；250 幀的 loss 差 `1.49e-8` 的十倍仍低於此底線，所以 loss 容差維持 `2e-6`。這是明列的工程選擇，不是由 machine epsilon 保證的誤差界，也不是研究證實的訓練近似門檻。

## 待選：是否加上相對上限

250 幀時梯度最小的參數群（三個蛋白都是 `ipa_layers.1.mha_l`）reference RMS 約 `3.7e-7`，只比絕對容差 `1e-7` 大約 3.7 倍。只用絕對容差時，這類小範數群即使有約 27% 的相對差異也會通過。實測的完整涵蓋相對差異最大為梯度 `1.830876423125773e-05`、更新 `0.0015233179807189509`。

- **選項 A：只用絕對容差。** 與原提案相同。
- **選項 B：絕對容差之外，另加相對上限。** 對高於近零 cutoff 的群組，同時要求梯度相對差不超過 `2e-4`、更新相對差不超過 `2e-2`。數字以同一規則（控制最大值十倍後向上取 1／2／5）只從完整涵蓋控制取得。

## 近零分類

近零分類建議使用同一絕對噪聲尺度：梯度 reference RMS `<= 1e-7`、更新 reference RMS `<= 2e-6` 時，relative difference、norm ratio 與 cosine 記為 null，保留原始 norm、RMS 與絕對差。真正零值另外計數，單側零值與缺失群組明列，不能以 cosine=1 代替無定義方向。兩種幀數的控制中，唯一的零 reference 群組是停用的 `cell_summaries` 更新。

截斷 case 的 loss／gradient／實際更新仍只作描述；即使控制一致性通過，也不產生「訓練近似通過」的宣稱。
